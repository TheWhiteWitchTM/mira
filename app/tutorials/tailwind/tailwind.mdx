A class is a style. You put it on the element. `mt-4` is margin on the top. `text-sm` is a small size. You do not open a stylesheet to do that one thing.

This site is on Tailwind 4. The v3 steps (`npx tailwindcss init -p`, a `tailwind.config.js`, and `@tailwind base`) are the old path. A new project should start where this one did.

## The three files

Install the packages.

```bash
npm install tailwindcss @tailwindcss/postcss postcss
```

`postcss.config.mjs` is the whole PostCSS setup.

```js
const config = {
  plugins: {
    "@tailwindcss/postcss": {},
  },
}

export default config
```

The stylesheet starts with one import. That import is the setup. v4 finds your templates. You do not list `content` paths unless classes are coming from a place it cannot see.

```css
@import "tailwindcss";

@theme {
  --font-sans: var(--font-geist-sans), system-ui, sans-serif;
}
```

`@theme` is where a value becomes a utility. The line above is why `font-sans` on this site is Geist. You do not keep a second config file for that.

In a React file the attribute is `className`. In an HTML file it is `class`. Mixing them up is the usual first bug. The browser then has no class, and the element looks unstyled.

## Build a line, one class at a time

Start with the words.

```html
<p>The lab is open.</p>
```

Size and weight:

```html
<p class="text-3xl font-semibold tracking-tight">The lab is open.</p>
```

`text-3xl` is the size. `font-semibold` is the weight. `tracking-tight` pulls the letters in, which is what you want on a large line. `text-balance` keeps a two-line heading from leaving one word alone on the second line.

Color and space:

```html
<p class="mt-2 max-w-md text-sm text-zinc-400">Tools, tutorials, and the dev blog.</p>
```

`mt-2` is margin on the top. `max-w-md` stops the line from running the full width of a monitor. `text-sm` is body size for a secondary line. `text-zinc-400` is a gray that still reads on black.

The spacing scale is the same everywhere. `1` is 0.25rem. `2` is 0.5rem. `4` is 1rem. `p-4` is padding on all sides. `px-3` is the left and right. `py-2` is the top and bottom. `gap-4` is the space between children of a flex or grid parent.

`space-y-2` also spaces children, and it fights `gap` if you put both on the same parent. Pick `gap`.

## The phone comes first

An unprefixed class is the narrow screen. `sm:` is the next step up, then `md:`, then `lg:`. You write the phone, then you add what changes when there is room.

```html
<h1 class="text-3xl sm:text-5xl">Mira</h1>
<ul class="grid grid-cols-1 gap-3 sm:grid-cols-2 lg:grid-cols-3"></ul>
```

One column on a phone. Two from `sm`. Three from `lg`. The gap stays.

Hide a sidebar until the page can hold it:

```html
<aside class="hidden md:block">Desk</aside>
```

`hidden` is `display: none`. `md:block` puts it back from the `md` width up. This site's side columns use that. Below `md` they are not in the way.

A row that wraps, instead of overflowing:

```html
<div class="flex flex-col gap-3 sm:flex-row sm:items-center">
  <div class="h-12 w-12 shrink-0 rounded-full bg-green-600"></div>
  <p class="text-sm text-zinc-300">Stacks on a phone. Sits in a row from sm up.</p>
</div>
```

`flex-col` stacks. `sm:flex-row` turns it into a row. `sm:items-center` lines the text up with the circle. `shrink-0` stops the circle from being squashed when the row gets tight. `min-w-0` on a grid child that holds a long word stops that word from blowing the column out. Links do this. Put `min-w-0` on the child, and `truncate` if the word itself should cut.

## The card on the home page

The portrait sits beside the words from `sm` up. On a phone the portrait is on top and the words follow. This is the pattern.

```tsx
export function Card() {
  return (
    <article className="grid grid-cols-1 overflow-hidden rounded-2xl border border-green-600/40 sm:grid-cols-[12rem_minmax(0,1fr)]">
      <div className="min-h-48 bg-black sm:min-h-full" />
      <div className="flex flex-col gap-3 p-5">
        <p className="text-xs font-medium uppercase tracking-[0.16em] text-green-600">Mira</p>
        <h2 className="text-3xl font-semibold tracking-tight">The lab</h2>
        <p className="text-sm text-zinc-400">Tools, tutorials, and the dev blog.</p>
      </div>
    </article>
  )
}
```

What each piece is doing:

- `grid grid-cols-1` is one column, so the portrait stacks above the words.
- `sm:grid-cols-[12rem_minmax(0,1fr)]` is two columns once there is room. The portrait is 12rem. The words take the rest, and `minmax(0, 1fr)` is what lets them shrink instead of overflowing.
- `overflow-hidden` plus `rounded-2xl` clips the portrait to the rounded corner.
- `border-green-600/40` is a green border at 40% opacity. The `/40` is the alpha. It works on backgrounds too, as in `bg-green-600/20`.
- `uppercase tracking-[0.16em]` is the small label. The tracking value is arbitrary because the scale has no step at `0.16em`. Arbitrary values are for that one-off. A width the scale already has should use the scale, `w-48`, not `w-[192px]`.
- `p-5` is the padding inside the words. `gap-3` is the space between the label, the title, and the line.

## Dark

This site toggles a `dark` class on the `html` element. The variant is declared once.

```css
@custom-variant dark (&:is(.dark *));
```

```tsx
<p className="text-zinc-900 dark:text-zinc-50">Readable either way.</p>
```

Put the light color first and the `dark:` color second. If you only set the dark color, the light theme inherits something you did not pick, and noon looks like a bug.

Borders and surfaces follow the same pair. `bg-white dark:bg-zinc-950`. `border-zinc-200 dark:border-zinc-800`.

## A row of links

The contact row on the home page is this, and it is the piece that usually breaks on a phone if you forget `flex-wrap`.

```html
<ul class="flex flex-wrap gap-2">
  <li>
    <a class="inline-flex rounded-full border border-green-600/50 px-3 py-1.5 text-sm" href="/">
      Home
    </a>
  </li>
  <li>
    <a class="inline-flex rounded-full border border-green-600/50 px-3 py-1.5 text-sm" href="/tools/">
      Tools
    </a>
  </li>
</ul>
```

`flex-wrap` lets the chips drop to the next line. `gap-2` is the space, in both directions, so you do not need margins on the items. `inline-flex` keeps the padding wrapped tight around the word. `rounded-full` is the pill. `px-3 py-1.5` is the hit area, big enough for a thumb.

## Where it goes wrong

- Starting from a v3 guide and adding `tailwind.config.js` plus the three `@tailwind` lines. On v4 that file is optional, and those directives are gone.
- Writing an arbitrary width for a step the scale already has.
- Setting both `space-y-4` and `gap-4` on the same parent. The children end up with two spacing systems.
- Forgetting `min-w-0` on a grid child that holds a long link.
- Forgetting `flex-wrap` on a row of buttons. The last button falls off the phone.
- Setting only `dark:` colors. Check the page with the theme toggle, in both directions.
- Using `class` in a React component. The style never arrives.

The full scale is the Tailwind docs: [tailwindcss.com/docs](https://tailwindcss.com/docs). When a class on this page and a class in those docs disagree, this site is on v4, and the docs page has a version switch.
