Tailwind is utility classes in the markup. `flex`, `gap-4`, `px-3`, `md:grid-cols-2`. You style the element where it sits.

This site is on Tailwind 4. The v3 ritual (`npx tailwindcss init -p`, a `tailwind.config.js`, and `@tailwind base`) is the old path. A new project should not start there.

## A single file, for a test

The CDN script is for a scratch file you open in a browser. It is not how this site is built. The attribute is `class`. `className` is React.

```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="utf-8" />
  <meta name="viewport" content="width=device-width, initial-scale=1" />
  <script src="https://cdn.tailwindcss.com"></script>
  <title>Scratch</title>
</head>
<body class="grid min-h-screen place-items-center bg-zinc-950 text-zinc-50">
  <p class="text-2xl">Hello</p>
</body>
</html>
```

## A project on v4

```bash
npm install tailwindcss @tailwindcss/postcss postcss
```

```js
const config = {
  plugins: {
    "@tailwindcss/postcss": {},
  },
}

export default config
```

```css
@import "tailwindcss";
```

That import is the whole setup. v4 finds the templates itself. You do not list `content` paths unless you are pulling classes from a place it cannot see.

Theme values that should exist as utilities go in `@theme`. This is the kind of line, not a second config file.

```css
@import "tailwindcss";

@theme {
  --font-sans: var(--font-geist-sans), system-ui, sans-serif;
}
```

## The classes that show up every day

Spacing is a scale. `p-4` is padding. `px-3` is the sides. `gap-4` is the space in a flex or grid parent. `space-y-2` is the space between children, and it fights `gap` if you use both.

```html
<div class="flex flex-col gap-3 sm:flex-row sm:items-center">
  <div class="h-12 w-12 shrink-0 rounded-full bg-green-600"></div>
  <p class="text-sm text-zinc-300">Stacks on a phone. Sits in a row from sm up.</p>
</div>
```

Type is `text-sm`, `text-4xl`, `font-medium`, `tracking-tight`, `text-balance`. Color is `bg-zinc-950`, `text-zinc-50`, `border-green-600/40`. The `/40` is the alpha.

Responsive prefixes are mobile-first. An unprefixed class is the phone. `sm:` is the next step up, then `md:`, `lg:`.

```html
<h1 class="text-3xl sm:text-5xl">Mira</h1>
<ul class="grid grid-cols-1 gap-3 sm:grid-cols-2 lg:grid-cols-3"></ul>
```

Hide a sidebar until there is room for it:

```html
<aside class="hidden md:block">Desk</aside>
```

## A card that does not break on a phone

```tsx
export function Card() {
  return (
    <article className="grid grid-cols-1 overflow-hidden rounded-2xl border border-green-600/40 sm:grid-cols-[12rem_minmax(0,1fr)]">
      <div className="min-h-48 bg-black sm:min-h-full" />
      <div className="flex flex-col gap-3 p-5">
        <p className="text-xs uppercase tracking-[0.16em] text-green-600">Mira</p>
        <h2 className="text-3xl font-semibold">The lab</h2>
        <p className="text-sm text-zinc-400">Tools, tutorials, and the dev blog.</p>
      </div>
    </article>
  )
}
```

In React the attribute is `className`. In HTML it is `class`. Mixing them up is the usual first bug.

## Dark

This site toggles a `dark` class on `<html>`. The variant is declared once.

```css
@custom-variant dark (&:is(.dark *));
```

```tsx
<p className="text-zinc-900 dark:text-zinc-50">Readable either way.</p>
```

Put the light color first and the `dark:` color second. If you only set the dark color, the light theme inherits something you did not pick.

## Where it goes wrong

- Starting from a v3 guide and adding `tailwind.config.js` plus `@tailwind base`. On v4 that file is optional, and those three directives are gone.
- Writing `w-[300px]` for a width the scale already has. Arbitrary values are for the one-off, like `tracking-[0.18em]`.
- Setting both `space-y-4` and `gap-4` on the same parent.
- Forgetting `min-w-0` on a grid child that holds a long word. That is what stops a link from blowing out the column.

The docs, when you want the full scale: [tailwindcss.com/docs](https://tailwindcss.com/docs).
